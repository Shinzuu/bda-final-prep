Pool · MCQQ9.1 Edward Tufte's data-ink ratio principle states that a visualization should: (a) Use more colours to highlight different categories of data (b) Maximise the fraction of ink devoted to representing actual data, removing all decorative elements (c) Use ink sparingly to reduce printing costs (d) Always include data labels using a different ink colour from the chart body

(b). Data-ink ratio = data-ink / total ink. It measures what the ink encodes, not how much ink you use. So (c) is the classic distractor.

Pool · MCQQ9.2 Which visualization type is most appropriate for showing the distribution and spread of a continuous variable? (a) Pie chart (b) Line chart (c) Histogram (d) Treemap

(c) Histogram. It bins a continuous variable to show shape and spread. Pie = part-to-whole. Line = change over time. Treemap = hierarchy.

Pool · MCQQ9.3 Shneiderman's visualization mantra begins with which step? (a) Details first, then overview (b) Overview first, zoom and filter, then details on demand (c) Filter first, then provide an overview (d) Details on demand first, then zoom out

(b) Overview first, zoom and filter, then details-on-demand. The overview shows the user what to filter, so filtering comes after it.

Pool · MCQQ9.4 Which visualization tool is best suited for a real-time production operations dashboard monitoring server metrics and application error rates with 5-second refresh intervals? (a) Tableau (b) D3.js (c) Power BI (d) Grafana

(d) Grafana. It reads time-series databases (InfluxDB, Prometheus) natively and refreshes every second. Tableau and Power BI refresh on a schedule. D3 needs custom WebSocket code.

Pool · T/FQ9.5 A pie chart is a recommended choice for comparing more than 5 categories.

False. Beyond ~5 categories, people judge arc angles poorly. A horizontal bar chart sorted by value is easier to read.

Pool · T/FQ9.6 Hexbin plots are an effective technique for reducing overplotting when visualising millions of data points.

True. Hexbin groups points into hexagonal cells and colours each by count. Density stays readable where a scatter plot becomes a solid blob.

Pool · T/FQ9.7 D3.js generates static PNG or PDF image files as its primary output format.

False. D3 binds data to SVG/DOM elements in the browser. The output is interactive vector graphics that update dynamically. It is not a static image.

Pool · T/FQ9.8 Choropleth maps are used to visualise the geographic distribution of a quantitative variable.

True. A choropleth shades geographic polygons (districts, countries) by colour intensity to show a quantity, e.g. dengue incidence per 100,000.

Pool · DescriptiveQ9.9 D1. Explain Tufte's data-ink ratio principle. Give a before-and-after example: describe a cluttered bar chart (what chart-junk elements are present) and the clean version after applying the principle.

Principle: data-ink ratio = ink used to show data / total ink. Maximise it. Erase non-data ink and redundant data ink (chartjunk), within reason.

Before: 3-D bars with gradient fill, heavy dark gridlines, thick chart border, shaded background, boxed legend, y-axis starting at a non-zero value, decorative clip-art.

After: flat single-colour 2-D bars. Y-axis from 0. No border or background. At most one light reference line. Direct labels on bars instead of a legend. Bars sorted by value. The data is the same, with less ink, so the chart reads faster and more honestly.

Pool · DescriptiveQ9.10 D2. What is overplotting? Describe three techniques to address it when visualising millions of points in a scatterplot. For each, explain what information it preserves that the overplotted chart lost.

Overplotting: so many marks overlap that the plot becomes a solid blob. Density and structure disappear (from roughly 104–105 points).

  1. Alpha transparency: dense areas look darker. This keeps relative density in moderately crowded regions.
  2. Hexbin / 2-D binning: counts points per hexagon and colours by count. This keeps quantitative density (actual counts per cell), even at millions of points.
  3. 2-D KDE contours (or sampling + KDE): a smooth density surface. This keeps the shape and location of clusters/peaks.

(Also valid: random sampling, Datashader server-side rasterisation.)

Pool · DescriptiveQ9.11 D3. What is a data cube? How does pre-aggregating a billion-row fact table into a data cube enable interactive visualization at sub-second latency? What is the trade-off?

Data cube: a multidimensional pre-aggregation of a fact table over all combinations (cuboids) of its dimensions. n dimensions give 2n cuboids.

Why fast: the group-by results (e.g. revenue by region × month) are computed once offline. A dashboard query reads a few thousand pre-summed rows instead of scanning 109 rows. Slice, dice and roll-up become lookups, so response is sub-second.

Trade-off: extra storage and build time (exponential in dimensions, large for high-cardinality dims). The cube is stale until refreshed. You lose row-level detail and any dimension not in the cube.

Pool · ProgrammingQ9.14 Live Exercise (Part 2): build a minimal D3.js bar chart of weekly Kafka message counts for 5 topics (generate 7×5 random values) that follows Tufte: (1) no gridlines (or one light reference line); (2) y-axis starts at 0; (3) no fill gradient, flat colour; (4) tooltip on hover (details-on-demand); (5) a sparkline per bar showing the 7-day trend. Extension: dropdown filter to select one topic and zoom into its 7-day line chart.
const y = d3.scaleLinear()
  .domain([0, d3.max(data, d => d.count)])  // starts at 0
  .range([h, 0]);
svg.selectAll(".bar").data(data).join("rect")
  .attr("class", "bar")                    // flat fill, no gradient
  .attr("x", d => x(d.topic)).attr("width", x.bandwidth())
  .attr("y", d => y(d.count)).attr("height", d => h - y(d.count))
  .on("mouseover", (e, d) => tip.style("opacity", 1)
      .html(d.topic + ": " + d.count))      // details on demand
  .on("mouseout", () => tip.style("opacity", 0));
// sparkline: d3.line() over d.week (7 values) drawn under each bar
svg.append("g").call(d3.axisLeft(y).ticks(4)); // no gridlines

Key idea: the data join binds each topic to a rect. Tufte = zero baseline, flat colour, no grid. Shneiderman = tooltip (details) and dropdown (filter/zoom).

Book ch09 · ShortQ9.18 What is Anscombe's Quartet? What property of summary statistics does it illustrate, and what does this imply about the role of visualization in data analysis?

Anscombe's Quartet is four x–y datasets with (nearly) identical mean, variance, correlation (r ≈ 0.82) and regression line. Their plots differ completely (linear, curved, outlier-driven, vertical cluster). Summary statistics can hide structure. So always plot the data before trusting statistics.

Book ch09 · ShortQ9.19 Define Tufte's data-ink ratio. Identify three specific chart elements that commonly lower the data-ink ratio and should be removed.

Data-ink ratio = data-ink / total ink used in the graphic (the share of ink that encodes data). Remove heavy gridlines, 3-D effects / gradient fills, and chart borders and background shading (also redundant legends and decorative icons).

Book ch09 · ShortQ9.20 A bar chart shows four annual revenue figures. Revenue changed from 82M in 2022 to 90M in 2023, a 9.8% increase. The y-axis starts at 80M. The 2023 bar appears five times taller than the 2022 bar. Calculate Tufte's lie factor.

Lie factor = size of effect shown in graphic / size of effect in data

  1. Data effect = (90 − 82)/82 = 0.0976 = 9.76% (≈ 9.8%).
  2. Bar heights above the 80M baseline: 2022 = 2, 2023 = 10, ratio 5×. Graphic effect = (10 − 2)/2 = 400%.
  3. Lie factor = 400 / 9.76 = 41.0.

Meaning: the chart exaggerates the growth about 41-fold. An honest chart has lie factor 0.95–1.05, so the axis must start at 0.

Small multiples are a grid of the same small chart repeated for each subset, with shared axes and scale. The eye compares them side by side. Example: the NYT 50-state grid of COVID-19 daily-case lines (one mini line chart per state, same y-scale). It beats an animated map. Book ch09 · ShortQ9.23 What is overplotting? At what approximate number of data points does it typically become a problem in a standard scatterplot?

Overplotting is when markers overlap so heavily that density, clusters and outliers become invisible (a solid blob). It usually starts at about 10,000 points (104). It is severe beyond ~100,000.

Book ch09 · ShortQ9.24 Describe the hexbin technique for addressing overplotting. What does it show that alpha transparency cannot?

Hexbin tiles the plane with hexagons, counts the points in each, and colours each hexagon by its count on a sequential colour scale with a legend. Alpha saturates to full opacity once enough points overlap. Hexbin shows actual quantitative counts, so it can tell 10,000 points from 1,000,000 in the densest regions.

Book ch09 · ShortQ9.25 What is a data cube? If a fact table has four dimensions (date, region, category, channel), how many cuboids does the full data cube contain?

A data cube is the set of all group-by aggregations of a fact table over every subset of its dimensions. Each aggregation is a cuboid.

Cuboids = 2n (no hierarchies)

  1. n = 4
  2. 24 = 16 (from the 4-D base cuboid down to the 0-D apex "all").

Meaning: 16 pre-computed group-bys cover every slice a dashboard can ask on those four dimensions.

Book ch09 · ShortQ9.26 Explain the difference between a periodic poll and a WebSocket push architecture for streaming visualization. Give a use case where each is appropriate.

Periodic poll: the client re-queries the server every N seconds. It is simple and stateless, but adds up to N s latency and wasted requests. Use: a Grafana ops dashboard refreshing every 30 s, or an hourly sales report.

WebSocket push: a persistent connection. The server sends each update as it happens. Latency is low, but servers are stateful. Use: live election results, fraud alerts or trading tickers that need sub-second updates.

Book ch09 · ShortQ9.28 What is the Shneiderman treemap? Explain how area and colour are used to encode two variables simultaneously.

A treemap (Shneiderman, 1992) shows a hierarchy as nested rectangles that fill the space. Area encodes one quantity (e.g. market cap, disk size, sales). Colour encodes a second (e.g. % daily change, growth, sentiment). Example: a stock-market map where big boxes are big companies and red/green shows price change.

Book ch09 · ShortQ9.29 Why does Tufte argue that 3-D effects on bar charts lower the data-ink ratio and increase the lie factor?

The side and top faces, shading and depth are non-data ink, so the data-ink ratio falls. Perspective also makes it unclear whether to read the front or back edge. The extra dimension makes the bar's apparent size (area/volume) grow faster than the value. The visual effect then exceeds the data effect: lie factor > 1.

Book ch09 · ProgrammingQ9.37 Pre-Aggregated Data Cube (PySpark). For a simulated 100-million-row e-commerce fact table (order_date, region, category, revenue_usd): generate the rows with Spark random functions; use DataFrame.cube() to materialise all cuboids over (order_date, region, category); write as Parquet partitioned by order_date; simulate three Tableau/Superset queries (date-range filter, region filter, group by category) against cube and raw table, timed with time.perf_counter(); report cube size in MB and speedup per query.
from pyspark.sql import functions as F
raw = (spark.range(100_000_000)
  .withColumn("order_date", F.expr("date_add('2024-01-01', cast(rand()*365 as int))"))
  .withColumn("region", (F.rand()*10).cast("int"))
  .withColumn("category", (F.rand()*20).cast("int"))
  .withColumn("revenue_usd", F.rand()*500))
cube = (raw.cube("order_date", "region", "category")
  .agg(F.sum("revenue_usd").alias("rev"), F.count("*").alias("n")))
cube.write.partitionBy("order_date").parquet("cube/")
t = time.perf_counter()
spark.read.parquet("cube/").filter("region=3 AND category IS NULL").count()
print(time.perf_counter() - t)   # repeat on raw; speedup = t_raw / t_cube

3 dimensions give 23 = 8 cuboids. NULL marks the rolled-up ("all") level. Cube rows are bounded by (365+1)(10+1)(20+1) = 84,546, far below 108, so queries run much faster (check size with du -sh cube/).
