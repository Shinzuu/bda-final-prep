Week 7 — Hive

Hive architecture and query compilation

Week 8 — Kafka, pipelines, lakes

Kafka: topic, partitions, brokers, consumer groups

Each group gets every event, with its own offsets. Inside a group one partition → one consumer. Order only within a partition. Leader dies → follower becomes leader.

Lambda architecture

Weak point: same logic coded twice (batch + speed) and kept in sync. Example: 1,200,000 (batch) + 85,000 (speed) = 1,285,000.

Kappa architecture

One code path. Reprocess = replay the log. Replay must be faster than live input: t = history ÷ (speed − live rate).

Batch ingestion: Sqoop and Flume

Sqoop: tables RDBMS ↔ HDFS, batch. Flume: logs → HDFS; file channel survives a crash, memory channel is faster but loses events. Kafka: real-time, any → any, replay.

Bank pipeline (Lambda, A1)

Data lake layers

Lake = schema-on-read, raw. Warehouse = schema-on-write, clean tables. Lake without governance = data swamp.

Week 9 — Visualization

Data-ink: before and after

Data-ink ratio = data ink ÷ total ink; maximise it. If erasing it loses no information, erase it. Lie factor = effect shown ÷ effect in data.

Shneiderman's mantra

Chart for each data type

Distribution = histogram · part-of-whole (≤ 4) = pie · rate by region = choropleth · count by place = bubble map · millions of points = hexbin.

Big-data dashboards: batch and streaming

Never send raw events to the browser: send one aggregate per window (3,000/s × 60 s = 180,000 events → 1 point).
